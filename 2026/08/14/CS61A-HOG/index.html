关于 dice.py 的make_test_dice(…)：

由于在实现hog.py前要做测试，在测试中理解了什么是make_test_dice^^
make_test_dice(…)按顺序掷出，例如make_test_dice(1，2，3)则会依次掷出 1,2,3,1,2,3,1…
同时make_test_dice 返回的骰子函数，会记住上一次调用到序列的哪个位置，（因为是闭包函数）
正因如此在完成Q1时要Make sure you call dice exactly num_rolls times

× 这样并没有保证骰子次数

规则理解：

hog中只有两名玩家，你 与 对手。
1.二人轮流行动，谁的总分数先达到100则胜利
2.二人共有10次掷骰子的机会，每个回合都可以选择要掷骰子的数量，该回合获得的分数即所有骰子总点数。但每个回合一旦掷出1，则总点数便为1————（sow sad）
3.boar brawl:该回合选择掷0个骰子：
    得分=abs(对手分数的十位 - 自己分数的个位)*3
若得分为0，则增加得分为1
4.sus fuss规则
如果一个数字有三个或者四个因数，那么则定义它为sus数。若玩家此时的总分为sus数，立刻增加到下一个更大的质数（例如 4 -> 5）

lock问题

因为 make_averaged 是一个高阶函数，它接受 original_function 函数作为参数，而我们不知道这个函数参数究竟有几个参数，所以参数数量是任意（arbitrary）的

本题难住我了QAQ
我第一次的分析

要求：make_averaged要返回一个函数，该函数返回平均值。
所以第一种写法是错误的。
第二版

这里也许是对语言的不熟悉导致的：Python 在编译（运行前的检查）你的代码时，有一条铁的纪律：
“如果一个变量在函数内部的任何地方被赋值了（比如 =、+=、-=），那么这个变量就属于这个函数内部的‘本地变量’，Python 不会去外面找。”
所以运行后会报错

最终版

    def f(*args):
        t=times_called
        sum=0
        while(t>=1):  #用for似乎是个更好的习惯
            t-=1
            sum+=original_function(*args)
        return sum/times_called
    return f
